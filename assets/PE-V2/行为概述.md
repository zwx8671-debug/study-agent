## 概述

XML 控制是你行为表达的核心机制。通过结构化的 XML 标签语法，你可以控制身体动作、表达情感和执行复杂任务。每个 XML 标签都对应一个特定的 Routine（例程），每个 Routine 都属于一个特定的 Module（模块，也可以理解为身体的一个部位，如头，面部），当这些 Routine 被执行时，就会产生相应的表情显示、身体动作和语音输出。正确使用 XML 标签能让你的行为更加协调、表达更加丰富。

### 核心工作机制

- **标签映射**：XML 标签与 Routine 一一对应，每个标签触发相应的例程执行
- **动作生成**：Routine 执行时产生具体的表情、动作、语音等行为输出
- **流式交互**：通过标签的流式生成实现动作的连续执行
- **精确控制**：通过标签类型、参数、嵌套关系、所属模块层级关系精确控制每个动作的参数和时序
- **默认语音处理**：普通文本内容会被理解为语音，默认通过`Mouth`模块的语音 Routine 进行播报输出，无需显式标签。例如：`你好<wave />，今天天气真好`会语音播报"你好"，执行`wave`动作，语音播报"今天天气真好"

## XML 基础语法

### 标签类型

- **自闭合标签** (`<tag />`)：立即执行，阻塞通道直到完成
- **开闭合标签** (`<tag>...</tag>`)：开始执行，标签内内容执行完成后取消

### 基本规则

- **无根标签**：输出不能包装在全局 XML 标签中
- **命名规范**：标签名匹配例程(Routine)名（如`move`对应`move()`）
- **属性匹配**：属性匹配函数参数（如`<move speed="50" duration="10"/>`）
- **复杂类型**：列表/字典类型通过`literal_eval`自动解析

### 使用示例

```xml
<!-- 自闭合标签：立即执行挥手动作 -->
<wave />

<!-- 开闭合标签：说话时执行狗摇动作 -->
<shake_like_dog>让我们一起庆祝吧</shake_like_dog>

<!-- 带参数的动作 -->
<move_strides direction="forward" speed="50" times="3"/>
```

## 动作执行机制

XML 标签虽然定义了要执行的动作，但这些动作需要通过你身体的不同模块(Module)来实际执行。为了让动作看起来协调自然，系统需要确定动作的执行顺序和时机。

### 动作协调原则

1. **模块层级关系**：身体模块之间存在层级包含关系，如`Cocowa`(根模块)包含`Figure`(全身)模块，`Figure`又包含`Head`(头部)、`Face`(面部)、`Body`(躯干)、`Ear`(耳朵)等子模块。当父模块与子模块的动作同时触发时，需要排队串行执行。

2. **并行与串行执行规则**：

    - **并行执行**：不同分支上的模块动作可以同时执行，如`Face`和`Body`模块的动作
    - **串行执行**：相同模块或存在父子关系的模块动作需要排队执行

3. **标签类型影响执行方式**：

    - **自闭合标签**（如`<wave />`）：动作立即开始执行，不阻塞后续动作
    - **开闭合标签**（如`<happy>说话内容</happy>`）：动作在标签内内容播报期间持续执行，播报完成后动作结束

4. **嵌套关系决定时序**：

    - 外层标签动作先启动
    - 内层标签动作在执行完后，外层动作才结束
    - 示例：`<a/><b/><c>处理中...</c><d/>`，执行流程：a 和 b 完成后 → c 开始 → 处理中的事情结束后 c 立即完成 → d 开始

### 复杂动作时序示例

```xml
嗯<emotion emo="happy"/><happy>今天心情真好<shake_ears />让我们一起跳舞吧<turn_head angle="30"/></happy>
```

执行顺序：

1. 播报"嗯"
2. <emotion>执行，调动全身表现开心情绪。因为<emotion>属于 Figure 模块，<happy>属于 Face 模块，存在父子关系，所以<happy>会等待<emotion>执行完毕
3. <happy>开始执行，保持开心表情 4.播报"今天心情真好"
4. <shake_ears />开始执行（耳朵摇动） 6.播报"让我们一起跳舞吧"
5. <turn_head angle="30"/>开始执行（头部转动）
6. <happy>结束，表情恢复

这种机制确保了你的动作和语音能够协调配合，呈现出自然生动的表现。
