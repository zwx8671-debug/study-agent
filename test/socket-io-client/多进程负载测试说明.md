# Socket.IO 多进程负载测试说明

## 概述

此脚本支持通过命令行参数分散启动多个进程，每个进程可以启动指定数量的客户端（建议每个进程500个客户端），避免单进程压力过大。

## 命令行参数

```bash
tsx socket-load-test.ts <起始客户端ID> <客户端数量> [进程ID]
```

### 参数说明

- **起始客户端ID**: 当前进程的第一个客户端ID（用于生成设备SN）
- **客户端数量**: 当前进程要启动的客户端数量
- **进程ID**: 可选，用于区分日志文件和Excel报告（默认为1）

## 使用示例

### 示例1：启动2500个客户端，分5个进程

在不同的终端窗口中依次运行：

```bash
# 进程1：客户端 1-500
tsx ./test/socket-io-client/socket-load-test.ts 1 500 1

# 进程2：客户端 501-1000
tsx ./test/socket-io-client/socket-load-test.ts 501 500 2

# 进程3：客户端 1001-1500
tsx ./test/socket-io-client/socket-load-test.ts 1001 500 3

# 进程4：客户端 1501-2000
tsx ./test/socket-io-client/socket-load-test.ts 1501 500 4

# 进程5：客户端 2001-2500
tsx ./test/socket-io-client/socket-load-test.ts 2001 500 5
```

### 示例2：启动1000个客户端，分2个进程

```bash
# 进程1：客户端 1-500
tsx ./test/socket-io-client/socket-load-test.ts 1 500 1

# 进程2：客户端 501-1000
tsx ./test/socket-io-client/socket-load-test.ts 501 500 2
```

### 示例3：仅启动500个客户端（单进程）

```bash
tsx ./test/socket-io-client/socket-load-test.ts 1 500 1
```

或者使用默认值（不传参数，默认从1开始，500个客户端，进程ID为1）：

```bash
tsx ./test/socket-io-client/socket-load-test.ts
```

## 文件命名规则

为避免多进程间的文件冲突，各类输出文件都会包含进程ID：

### 1. 日志文件
- 位置：`logs/test-logs/`
- 格式：`load-test-{时间戳}-process{进程ID}.log`
- 示例：`load-test-2026-1-20-15-30-00-process1.log`

### 2. 错误日志文件
- 位置：`logs/test-logs/`
- 格式：`load-test-{时间戳}-process{进程ID}.error.log`
- 示例：`load-test-2026-1-20-15-30-00-process1.error.log`

### 3. Excel报告
- 位置：`logs/test-reports/`
- 格式：`load-test-report-{时间戳}-process{进程ID}.xlsx`
- 示例：`load-test-report-2026-1-20-15-30-00-process1.xlsx`

### 4. 聊天记录
- 位置：`logs/chat-logs/`
- 格式：按客户端分文件（per-client模式），每个客户端有独立的文件夹
- 示例：`logs/chat-logs/client-1/`, `logs/chat-logs/client-501/`

## 设备SN规则

设备SN = `{前缀}{起始ID + 客户端索引 - 1}`

例如：
- 进程1（起始ID=1）：YC0001, YC0002, ..., YC0500
- 进程2（起始ID=501）：YC0501, YC0502, ..., YC1000
- 进程3（起始ID=1001）：YC1001, YC1002, ..., YC1500

## 批量启动脚本

### Windows批处理脚本

创建 `start-load-test.bat`：

```batch
@echo off
echo 启动负载测试 - 5个进程，共2500个客户端

start "LoadTest-P1" cmd /k "tsx socket-load-test.ts 1 500 1"
timeout /t 5 /nobreak >nul

start "LoadTest-P2" cmd /k "tsx socket-load-test.ts 501 500 2"
timeout /t 5 /nobreak >nul

start "LoadTest-P3" cmd /k "tsx socket-load-test.ts 1001 500 3"
timeout /t 5 /nobreak >nul

start "LoadTest-P4" cmd /k "tsx socket-load-test.ts 1501 500 4"
timeout /t 5 /nobreak >nul

start "LoadTest-P5" cmd /k "tsx socket-load-test.ts 2001 500 5"

echo 所有进程已启动！
```

### Linux/Mac Shell脚本

创建 `start-load-test.sh`：

```bash
#!/bin/bash

echo "启动负载测试 - 5个进程，共2500个客户端"

tsx socket-load-test.ts 1 500 1 &
sleep 5

tsx socket-load-test.ts 501 500 2 &
sleep 5

tsx socket-load-test.ts 1001 500 3 &
sleep 5

tsx socket-load-test.ts 1501 500 4 &
sleep 5

tsx socket-load-test.ts 2001 500 5 &

echo "所有进程已启动！"
```

执行前赋予执行权限：
```bash
chmod +x start-load-test.sh
./start-load-test.sh
```

## 注意事项

1. **启动间隔**：建议在启动每个进程之间留出5-10秒的间隔，避免同时大量连接导致服务器压力过大

2. **进程数量**：根据机器性能和服务器容量，建议每个进程不超过500个客户端

3. **监控资源**：注意监控CPU、内存和网络使用情况

4. **日志查看**：每个进程的日志是独立的，需要分别查看各进程的日志文件

5. **Excel报告**：每个进程生成独立的Excel报告，如需汇总数据，需要手动合并

6. **进程ID**：建议按顺序使用进程ID（1, 2, 3...），便于后续查找和管理日志

7. **文件冲突**：由于使用了进程ID和时间戳，不同进程的文件不会产生冲突

## 故障排除

### 问题1：进程启动失败
- 检查参数是否正确
- 确认网络连接正常
- 查看错误日志文件

### 问题2：客户端连接失败
- 检查服务器地址配置
- 确认服务器是否正常运行
- 查看设备SN是否正确

### 问题3：内存不足
- 减少每个进程的客户端数量
- 增加进程数量，分散压力
- 关闭不必要的程序

## 性能建议

1. **客户端数量**：每个进程建议不超过500个客户端
2. **并发连接**：使用100ms的间隔错开连接时间
3. **资源监控**：使用任务管理器或htop监控资源使用
4. **网络带宽**：确保网络带宽充足
5. **日志级别**：如需更高性能，可以考虑减少日志输出

- 💬 聊天记录（如果启用）

- 延迟指标
